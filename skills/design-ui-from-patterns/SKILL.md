# UI設計パターン

目的、利用者、制約から設計パターンを選び、具体的な事例を読み、今回の画面に適応し、操作で確認する。IF–THENは適用条件に使い、理由・トレードオフ・事例・例外を一緒に判断する。

## 実行上の前提

- ユーザーの依頼、実行環境の権限、対象プロジェクトの指示を優先する。登録・公開・実装をこのスキルだけで新たに許可しない。既に依頼された作業の承認を取り直さない。
- このフォルダ一式が1つのスキルである。相対パスはこのSKILL.mdのディレクトリを基準に解決する。特定サービス、モデル、プラグイン、ネット接続は必須にしない。
- 内容はゲームUIの解説トランスクリプトを構造化した設計知識であり、利用者調査全般やアクセシビリティ規格への適合を保証しない。
- 事例は設計を考える材料として扱う。ゲームの現行仕様、実験結果、見ていない画面の詳細を断言しない。原稿の「こういう画面」は画像の代わりにならない。
- 本文で「原稿」は話者の説明、「応用」はスキル編者の一般化、「確認」は提案する検証を意味する。これらを混ぜない。
- 参照資料を読めない場合は未読であることを明示する。読んだことにせず、利用者が渡した統合版、またはアクセスできる資料だけで扱える範囲を示す。

## 進め方

1. **依頼の種類を決める。** 新規設計、既存画面のレビュー、限定的修正のどれかを判定する。コードのみの修正で設計判断が変わらなければ、この知識を一律に追加しない。
2. **目的と制約を拾う。** 主な利用者、達成したい行為、利用頻度、端末・入力方法、対応言語、実際の利用環境、作品らしさ・ブランド、変更できない要件を、依頼と既存資料から抽出する。既に分かることを再質問しない。判断を変える不足だけを確認し、それ以外は仮定と記す。
3. **読む資料を選ぶ。** 下の表で課題に合うファイルを開き、適用条件を満たすカードとその事例を読む。作品名が指定された場合は事例索引も使う。全資料を毎回読む必要はない。
4. **適用を判断する。** 候補ごとに「共通する条件／異なる条件／採る工夫／調整または見送る工夫」を短く決める。未検証の原因を観測事実にしない。ゲーム外への応用では入力装置、操作頻度、失敗の影響、利用者の目的の違いを確認する。
5. **競合を解く。** 固定要件、利用可能性、主要タスクの達成と回復を満たしたうえで、作品らしさ、情報密度、操作速度などの優先順位を依頼に合わせて決める。演出の価値を自動的にゼロにせず、装飾のために必須情報も隠さない。同じ目的に複数案がある場合は条件と取引を説明して選ぶ。
6. **案に落とす。** 画面、遷移、文言、状態、設定項目のうち依頼されたものを具体化する。実装も依頼されていれば既存環境に合わせる。React等の実装にはuiスキルを任意で併用できるが、このスキル単体でも設計・レビューを完結できる。
7. **確かめる。** 選んだカードの確認項目とreview.mdの該当項目を使い、操作経路、別言語、入力方法、設定変更・復帰などを調べる。結果を「確認済み／未確認／今回の対象外」に分ける。静的に読んだだけでユーザーテスト済みとしない。
8. **結果を返す。** 主要な提案、理由、参考にしたパターン・事例、今回の調整点、検証結果を依頼に見合う量で返す。小さな文言修正に全項目の長文レポートを強制しない。

## 判断を固定する条件

- 「IF 優先度が違う THEN 大きさを変える」は検討候補であり、自動適用命令にしない。同等の選択肢、利用頻度不明、文字のはみ出しも考える。
- 「色分け」は色だけに意味を依存させる指示にしない。文字、形、位置なども合わせて確認する。
- 「決定を続けると基本体験へ進む」は、購入・削除・送信・権限変更へ連打で到達させる指示にしない。
- 「演出で待ちを埋める」は、処理が終わっても演出のために待たせる指示にしない。
- 「カスタマイズ」は、設定画面から戻れなくなるほど入力を奪う指示にしない。
- 「プリセット」は詳細調整を禁止する指示にしない。
- 原稿中の薬の話、右脳／左脳の説明、国別傾向、個人的好みは、普遍的な設計根拠へ昇格させない。ホイール案は未実装の提案として扱う。

## 出力の最小形

- 目的と重要な制約
- 提案する具体的な変更
- 参照したP-*とE-*、今回に適用する理由と調整点
- 確認済みのこと、未確認のこと、必要な次の確認

レビューなら「観測した問題 → 影響 → 修正案 → パターン／事例 → 確認方法」で記す。原稿の根拠と編者の応用を区別し、存在しない定量効果や厳密な画面寸法を加えない。

## 別のAIへ渡す

このフォルダを丸ごと渡す。SKILL.mdだけをコピーして参照ファイルを落とさない。標準のスキル読込に対応しない環境には、このフォルダ内のscripts/export_portable.pyで生成した統合Markdownを渡せる。統合版は派生物であり、修正は元ファイルへ反映して再生成する。自動選択やファイル読込の挙動は利用先の機能に依存する。
