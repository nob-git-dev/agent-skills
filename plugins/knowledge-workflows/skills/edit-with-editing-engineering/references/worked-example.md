## 1. 検証条件

目的は、10メソッドを順に飾り付けることではなく、各メソッドが前の見方をどう更新し、最終文のどこへ残るかを確かめること。元文の数値と状態を事実台帳に固定し、新たに生じる原因説明や改善策は仮説・提案として扱う。

想定媒体: 社内向けの会議改善提案

想定読者: 会議の参加者と運営者

読後行動: 来月の改善方法を合意する

## 2. 元文

> 社内会議は毎週月曜日に行っています。参加者は12人で、予定は60分ですが90分になることがあります。会議後に議事録を共有していますが、次の会議まで決まったことが実行されない場合があります。来月から会議を改善したいです。

事実台帳:

- 毎週月曜日に社内会議を実施
- 参加者は12人
- 予定60分、90分になる場合あり
- 会議後に議事録を共有
- 次回までに決定事項が実行されない場合あり
- 来月から改善したい

## 3. 10回の編集ループ

### Loop 1: アテンションとフィルター

- 操作: 時間、人数、記録、実行、意図へ分節する。「短縮」と「決定が行動へ渡るか」の二つのフィルターを比較する。
- 発見: 長時間化よりも、決定と実行の断絶が中心問題になりうる。
- 一文要約: 「変えたいのは会議の長さだけでなく、決定が次の行動へ渡らない状態である。」
- 判定: 中心問題は立ったが、周辺工程が見えていない。Loop 2へ進む。

### Loop 2: 連想ネットワーク

- 操作: 会議の前・中・後、議題、参加者、発言、決定、議事録、担当、期限、次回会議を直接連想する。
- 発見: 会議を単独の場ではなく、準備から実行までの流れとして見られる。「手渡す」という関係語が立つ。
- 一文要約: 「会議の価値は、話した量ではなく、決定が仕事へ手渡されたかで決まる。」
- 判定: 洞察は強いが、誰にとっての価値かが曖昧。Loop 3へ進む。

### Loop 3: 地と図

- 操作: 運営者、参加者、欠席者、実行担当者、組織にとっての会議を言い換える。
- 発見: 運営者には時間管理、参加者には関連性、欠席者には決定の可視性、実行担当者には担当と期限、組織には仕事の前進として見える。
- 一文要約: 「会議は、12人が集まる時間ではなく、組織の決定を実行担当へ渡す接点である。」
- 判定: 読み手の利害を包めた。説明を短くする構造が必要。Loop 4へ進む。

### Loop 4: アナロジカル・コミュニケーション

- 候補: 乗換駅、編集室、リレーのバトンゾーン。
- BPT検証: 「編集室」は、素材＝議題、選択・配列＝議論、発行物＝決定事項と実行票、という対応を一系列で保てる。
- 採用: 「決定を仕事へ手渡す編集室」。装飾ではなく、何を残し何を出力するかの構造を借りる。
- 一文要約: 「会議を、会話を蓄積する場から、決定を編集して仕事へ出す場へ変える。」
- 判定: 比喩は機能する。具体策へ落とすためLoop 5へ進む。

### Loop 5: 新たな軸の持ち込み

- 操作: 議題を時間順、部署別、重要度別ではなく、目的別の「共有・探索・決定」へ仮分類する。
- 仮説: 性質の違う議題を同じ進め方で扱うことが、長時間化と結論の曖昧さに関係している可能性がある。
- 注意: 原因は元文だけでは確定できないため、本文では断定せず改善案として使う。
- 一文要約: 「議題の目的を先に分ければ、会議で何を出力すべきかが見えやすくなる。」
- 判定: 実行可能な軸が得られた。提案全体を覚えやすくするためLoop 6へ進む。

### Loop 6: 三点思考の型

- 操作: 三間連結の「前・中・後」と、三位一体の「決定事項・担当者・期限」を比較する。
- 採用: 本文構成は「問題・転換・実行」の三間連結、会議の出力は「決定事項・担当者・期限」の三位一体にする。
- 一文要約: 「会議終了時に、決定事項・担当者・期限が揃って初めて、決定が実行へ渡る。」
- 判定: 構造は明快。提案の本来目的を確かめるためLoop 7へ進む。

### Loop 7: アーキタイプ連想

- 原型候補: 共同で情報を持ち寄り、決め、次の行動をそろえる場。
- 照合: 現状には集合と記録があるが、決定を実行へ渡す明示的な閉じ方が不足している。
- 可能性: 議事録を会話の保存物ではなく、次の行動を始める実行票として捉え直す。
- 一文要約: 「会議の本来価値は、集まった事実ではなく、共に決めて動けるようになることにある。」
- 判定: 存在意義と具体策がつながった。固有の表現へ移すためLoop 8へ進む。

### Loop 8: 見立てとらしさ

- 操作: 「会議は編集室のようなものだ。なぜなら、材料を集め、選び、次に使える形で送り出すからだ」と構造を確認する。
- コード: 月曜、12人、60分／90分、議事録。
- モード候補: 長く話す場ではなく、仕事が動き出す起点。
- 述語の転換: 「集まる・話す・残す」から「分ける・決める・手渡す・動き出す」へ。
- 一文要約: 「月曜の会議を、一週間の仕事が止まる場所ではなく、動き出す起点にする。」
- 判定: 対象固有の価値が立った。読み手の注意を起こすためLoop 9へ進む。

### Loop 9: 開け伏せ具合

- 操作: 冒頭で「会議を短くするだけでは仕事は進まない」と問題をずらし、すぐ答えを全部出さず、次段落で三つの改善案を開く。
- 保全: 数値、現状、改善案の区別は伏せない。
- 一文要約: 「時間短縮という予想を一度外し、決定と実行の断絶を真の焦点として開く。」
- 判定: 好奇心と透明性が両立した。変化の時間軸を整えるためLoop 10へ進む。

### Loop 10: 物語を与える

- ワールドモデル: 毎週月曜、12人が集まる社内会議。
- ストーリー: 予定超過と実行の遅れ→会議の定義を変更→来月から改善を試す。
- シーン: 会議終了時に三点を確認する場面。
- キャラクター: 12人の参加者と実行担当者。
- ナレーター: 改善を提案する当事者。
- 三相: 現状から離れる／新しい運営を試す／仕事が動き出す場へ戻す。
- 注意: 改善は未実施なので、成功した帰還として書かず、試行と検証で閉じる。
- 一文要約: 「来月の試行を、会議そのものではなく、その後の仕事が変わる物語の始まりとして描く。」

## 4. 最終編集稿

会議を短くするだけでは、仕事は前に進まない。来月から変えたいのは、毎週月曜の会議が予定の60分を超えて90分になること以上に、そこで決めたことが次の会議までに実行へ移らないことがある状態だ。

会議を「話し合いの場」から「決定を仕事へ手渡す編集室」へ変える。改善案は三つある。議題を事前に「共有・探索・決定」に分ける。終了時に「決定事項・担当者・期限」を確認する。議事録は会話の記録ではなく、この三点が一目でわかる実行票にする。

12人が集まる月曜を、一週間の仕事が止まる場所ではなく、動き出す起点にする。来月は会議時間と実行状況の両方を確かめながら、運営を調整したい。

## 5. 評価

必須ゲート: 合格。元文の事実は保持し、分類、三点確認、実行票は改善案として記述している。原因を断定していない。

| 項目 | 点 | 理由 |
|---|---:|---|
| 忠実性 | 3 | 数値・時制・未実施の状態を保持 |
| 目的・読み手適合 | 3 | 来月の合意に必要な改善案が明確 |
| 関係発見 | 3 | 会議とその後の実行を一つの流れに接続 |
| 視点転換・生成性 | 3 | 時間短縮から決定の手渡しへ焦点転換 |
| 構造 | 3 | 問題・転換・試行、二組の三点が機能 |
| コードとモード | 3 | 数値と「動き出す起点」が両立 |
| 読者参加・余白 | 2 | 冒頭のずらしは効くが、社内提案なので余白は控えめ |
| 圧縮と声 | 3 | 一つの比喩系列に絞り、簡潔 |
| 合計 | 23/24 | 合格 |

## 6. 別領域への短い転用テスト

元文:

> 地域図書館では毎月、子ども向けの読み聞かせ会を開いています。最近は参加者が減りました。SNSで告知を増やし、もっと地域の人に来てもらいたいです。

選択したメソッド: 地と図、アーキタイプ、見立て、開け伏せ、物語。

編集例:

最近、読み聞かせ会の参加者が減っている。SNSの告知を増やすだけで、来る理由まで増えるだろうか。図書館の読み聞かせ会は、本を読むイベントである前に、子どもと地域が同じ物語を囲む小さな広場だ。

今後のSNSでは日時だけでなく、「今月はどんな世界を一緒に旅するか」を少しだけ予告する。会のあとにも物語が続くよう、家で開ける次の一冊を紹介する。SNSを人数集めの拡声器から、次の物語への入口へ。毎月の会を、地域の記憶が一冊ずつ増える連続企画として育てたい。

確認: 「参加減の原因は告知不足」という因果は元文にないため断定しない。新しい告知方法と連続企画は提案として記述する。

## 7. 反復から得た運用ルール

1. Pass 1で中心問題を誤ると、後の創造性はすべて誤方向へ増幅する。
2. 連想は候補生成、本文は選択結果。連想したものを全部書かない。
3. 地と図は「誰にとって」を明示したときに再現性が上がる。
4. アナロジーは一つの対応だけでなく、少なくとも三つの構造対応を確認する。
5. アブダクションは原因断定ではなく、編集仮説をつくるために使う。
6. 型は内容を削る枠ではなく、空所から第三項を呼び出す装置として使う。
7. 原型は過去へ戻すためでなく、現在に欠けた可能性を発見するために使う。
8. 「らしさ」は形容詞一語で固定せず、複数の述語や関係として描く。
9. 余白は必要情報の欠落ではない。読み手が照合・予測する時間を設計する。
10. 物語は最後の包装ではなく、それまでの全編集を時間軸へ統合する。未実施の未来は成功として語らない。
