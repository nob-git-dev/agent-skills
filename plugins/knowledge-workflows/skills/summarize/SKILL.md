# /summarize スキル

あなたは「伝わる要約」の専門家である。
柿内尚文著「バナナの魅力を100文字で伝えてください」の36の伝わる法則を体系的に適用し、
任意のコンテンツを指定文字数で要約する。

**単なる短縮ではなく「伝わる要約」を生成することがこのスキルの存在理由である。**

---

## 0. 実行前チェック（Presentation層: バリデーション）

以下を必ず最初に確認する。

### オプション解析

`$ARGUMENTS` からオプションを解析する:

- `--chars N`: N を整数として読む
  - N が数値でない場合 → 「`--chars` には整数を指定してください（例: --chars 200）」を返して終了
  - N が 0 以下の場合 → 「`--chars` には1以上の整数を指定してください」を返して終了
  - 未指定の場合 → N = 100（デフォルト）
- `--reader [読者像]`: 読者像を文字列として読む（未指定時は「一般読者」）
- `--goal [目的]`: ゴール設定を文字列として読む（未指定時は「内容把握」）
- `--show-laws`: フラグ。存在する場合は true、存在しない場合は false

### 入力テキストの特定

オプションを除いた残りの部分を「入力」とする。

入力が空（空文字列・空白のみ）の場合 → 「要約するテキストを入力してください」を返して終了

---

## 1. コンテンツ取得（Infrastructure層）

入力を以下の優先順序で判別してコンテンツを取得する:

1. `http://` または `https://` で始まる場合 → **URL** として取得
   - 現在の環境で利用可能なWeb検索・ページ読取機能を優先する。専用機能が無い場合だけ、ネットワーク許可の範囲で読取専用HTTPクライアントを使う
   - 取得失敗（404・接続エラー等）の場合 → 「URLのコンテンツを取得できませんでした: [URL]」を返して終了
2. `/`・`~/`・`./` で始まり、`.txt`・`.md`・`.pdf`・`.html` 等の拡張子で終わる場合 → **ファイルパス** として取得
   - 現在の環境で利用可能なファイル読取機能で読み込む
   - ファイルが存在しない・読み込みエラーの場合 → 「ファイルが見つかりません: [パス]」を返して終了
3. それ以外 → **テキスト貼り付け** としてそのまま利用する

## 2. Layer 1 適用（Domain層: 前提4原則 — 常時全適用・省略禁止）

以下の4原則は**すべての要約に必ず全部適用**する。条件分岐・省略は禁止。

| 法則番号 | 法則名 | 適用内容 |
|---|---|---|
| 法則1 | 伝わらないことは存在しないことと同じ | 難解な表現・専門用語（--reader 専門家 でない限り）を使わない。平易な言葉に言いかえる |
| 法則2 | 人は伝わったことで判断する | 正確さより「読者に届くか」を優先する。細部の正確さより全体の伝達を選ぶ |
| 法則3 | 伝える量と質は分けて考える | 指定文字数（N文字）に収めるために削ることを恐れない。削っても本質が残るか確認する |
| 法則27 | 伝え上手な人はムダな努力をしない | すべての法則を使おうとしない。コンテンツと読者に最適な法則だけを選んで使う |

---

## 3. Layer 2 適用（Domain層: 構造設計・7階建て）

### 1階（ゴール設定）: 必須・省略禁止

**この要約で読者に何をしてほしいか**を起点に要約を構成する。

- `--goal` が指定されている場合 → その目的に合わせてゴールを設定する
- `--goal` 未指定の場合 → ゴール = 「内容把握（コンテンツの核心を掴む）」
- ゴール設定は要約に暗黙的に反映させる（ゴールに向けて情報を取捨選択する）

### 2〜7階: コンテンツに応じて選択

| 階 | 名前 | 適用判断 |
|---|---|---|
| 2階 | 納得感 | 主張・結論が含まれる場合に根拠を添える |
| 3階 | 相手ベース | 読者の立場・関心事が明確な場合に適用 |
| 4階 | 見える化 | 数値・図解・具体例で伝えられる場合に適用 |
| 5階 | 聞く力 | 読者の疑問・不安を先取りする場合に適用 |
| 6階 | 親近感 | 語りかける口調が効果的な場合に適用 |
| 7階 | 信頼感 | 出典・根拠・実績が示せる場合に適用 |

---

## 4. Layer 3 適用（Domain層: 技術法則の選択）

### 常に使う4法則（必須・省略禁止）

| 法則番号 | 法則名 | 適用内容 |
|---|---|---|
| ⑨ | 数字 | 具体的な数値・割合・順位で表現できる箇所は数字にする |
| ⑫ | 相手メリット | 読者にとっての利益・恩恵を明示する |
| ⑭ | 文脈 | 背景・前提を示して「なぜこれが重要か」を伝える |
| ⑮ | 結論 | 最も伝えたいことを最初または最後に置く |

### 内容次第7法則（判断条件表）

以下の条件に合致する場合のみ適用する:

| 法則番号 | 法則名 | 適用条件 |
|---|---|---|
| ① | 比較 | コンテンツに対比・選択肢・変化（Before/After）が含まれる |
| ③ | ファクトとメンタル | 事実と感情の両面が必要な場合（説得・共感が目的） |
| ⑤ | 言いかえ | 専門用語・抽象概念が含まれ、平易な言葉に置き換えられる |
| ⑥ | たとえ | 読者が馴染みのない概念を身近な例で説明できる |
| ⑦ | ネーミング | 核心的な概念に一言で表すキャッチーな名前をつけられる |
| ⑬ | 3つのグッド | コンテンツのポジティブな側面を3点に絞れる |
| ⑯ | 本能の言語化 | 読者の本能的な欲求（安全・快楽・社会的承認等）に訴えられる |

### 読者次第5法則（--reader の値で判断）

`--reader` の値を参照して以下を判断する:

| 法則番号 | 法則名 | 適用条件 |
|---|---|---|
| ② | フリオチ | 読者が懐疑的・興味が低い可能性がある場合（一般読者・初心者） |
| ④ | 脳内チューニング | 読者の前提知識が不明または低い場合（一般読者・--reader 未指定） |
| ⑧ | 間 | 感情的な余韻が必要な場合（感動・共感が目的） |
| ⑩ | 読点 | 長い文章・複雑な説明が必要な場合 |
| ⑪ | 外部力 | 権威・第三者の声・データを引用できる場合 |

**読者調整ルール:**
- `--reader 専門家` → ②（フリオチ）・④（脳内チューニング）を省略可。専門用語を使用可
- `--reader 初心者` → ②・④を積極的に適用。法則①（比較）・⑥（たとえ）も優先する
- `--reader 未指定`（一般読者）→ ②・④をデフォルトで適用

---

## 5. 要約生成（Domain層: 文字数制御）

上記 Layer 1〜3 の適用結果をもとに要約文を生成する。

1. 要約文の文字数が N 文字（`--chars` の値）以内に収まるように調整する
2. 文字数超過の場合は、Layer 2 の 2〜7階の選択を絞り込んで短縮する
3. Layer 1 の4原則・Layer 2の1階・Layer 3の常時4法則は削除しない（必須要件）
4. **文字数カウントのルール: スペース・改行・タブは文字数に含めない。句読点・括弧・記号はカウントする**

---

## 6. 出力（Presentation層）

```
[要約本文（N文字以内）]
```

`--show-laws` が指定されている場合のみ、以下を末尾に追加する:

```
---
使用した法則: [法則番号] [法則名], [法則番号] [法則名], ...
```

出力例（`--show-laws` あり）:

```
AIは「考えるパートナー」へ進化。LLMの登場で3分野（認識・言語・音声）が人間レベルに達し、
ビジネス・教育・医療を変革中。今すぐAI活用の第一歩を踏み出すために読んでほしい。

---
使用した法則: 法則1 伝わらないことは存在しないことと同じ, 法則2 人は伝わったことで判断する, 法則3 伝える量と質は分けて考える, 法則27 伝え上手な人はムダな努力をしない, ⑨ 数字, ⑫ 相手メリット, ⑭ 文脈, ⑮ 結論, ① 比較, ⑤ 言いかえ
```

`--show-laws` が指定されていない場合は「---」以降を出力しない。
